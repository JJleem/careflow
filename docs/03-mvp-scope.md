# 3. MVP 범위 및 근거

## 3.1 MVP 선정 기준

2주라는 기한 안에서 다음 세 기준으로 범위를 판정했다.

1. **근본 문제 직결성** — 문제 정의에서 도출한 3대 근본 문제(예약이 사람을 거침 / 상태 관리 부재 / 데이터로 남지 않음)를 직접 해결하는가. 셋 중 하나라도 빠지면 "상담 운영 전반 개선"이라는 과제 목표를 달성하지 못한다.
2. **End-to-End 완결성** — 고객 예약 → 리마인드 → 상담 진행 → 기록 → 지표 집계까지 하나의 흐름이 끊김 없이 동작해야 플랫폼으로서 검증 가능하다. 특정 구간만 깊게 파는 것보다 전 구간이 얇게라도 이어지는 것을 우선했다.
3. **외부 의존 최소화** — 외부 시스템(LIMS, 커머스, 알림톡)이 필요한 부분은 실물 연동 대신 **교체 가능한 어댑터 + 시드 데이터**로 대체하고, 연동 지점만 설계로 증명한다.

## 3.2 MVP 범위

### 포함 (구현)

| 영역 | 범위 | 해결하는 문제 |
|------|------|--------------|
| 계정/피검자 | JWT 로그인(고객·상담사·관리자 3역할), 가족 피검자 등록 | P2 |
| 검사 결과 | 피검자별 결과지 조회 (시드 데이터: 3종 서비스 × 지표 수치/해설) | 상담 컨텍스트 |
| QR 진입 | 결과지 QR(서명 토큰) 스캔 → 이름/전화 검증 → 결과지가 미리 선택된 예약 화면 진입 | P1 |
| 예약 | 상담사 가용 슬롯 등록 → 고객이 시간 기준 조회·즉시 예약·취소. 가용 상담사 자동 배정(부하 균형, 재상담 시 이전 상담사 우선), DB 제약 기반 이중 예약 차단 | P1, P3, P4 |
| 대기·추천 | 만석 시 인근 빈 슬롯 추천 + 대기 등록(취소 시 전원 알림·선착순) | P3 |
| 알림 | 인앱 알림 + 스케줄러 기반 자동 리마인더(24h/1h 전), 채널 어댑터 구조 | P5 |
| 상담 운영 | 상담사 당일 일정 + 예약 컨텍스트 뷰, 완료/노쇼 처리 | P5, P6 |
| 상담 기록 | 구조화 기록(요약/관심 제품/추천/후속 조치/구매 연결) 작성 | P6, P7 |
| **LLM ①** | 자유 메모 → 구조화 기록 자동 추출 (structured output) | P6 |
| **LLM ②** | 예약 확정 시 검사 결과 기반 상담사용 사전 브리핑 비동기 생성 | 상담 품질 |
| 구매 대사 | 구매 이벤트 목 웹훅(`/webhooks/purchase`) → 완료 상담과 자동 매칭해 구매 연결 갱신 | P7, P8 |
| 대시보드 | 상담 건수/완료율/노쇼율/전환율/관심 제품 순위 자동 집계 | P7, P8, P9 |

### 제외 (설계로만 명시)

| 항목 | 제외 근거 | 설계상 대비 |
|------|----------|------------|
| 실채널 알림(알림톡/SMS) | 외부 계약·비용 필요, 과제에서 검증 불가 | `NotificationChannel` 어댑터 인터페이스. 인앱 채널과 동일한 계약으로 추가만 하면 됨 |
| LIMS(검사 시스템) 연동 | 실데이터 접근 불가 | 결과지 스키마를 실제 구조(지표 수치+해설)로 모델링하고 시드로 주입 |
| GTM/GA4→BigQuery 구매 파이프라인 (FR-E6) | 자사몰이 가상이라 실검증 불가 | 구매 웹훅을 공급 지점으로 설계. 실운영에서는 ① 자사몰 주문 웹훅(source of truth) ② GA4 BigQuery export 배치 조인(몰 백엔드 미제어 시)이 이 웹훅을 호출 |
| SMS 본인인증(OTP) | 외부 발송 계약 필요 | QR 검증 단계(이름/전화 일치)에 OTP 어댑터 추가 여지 |
| 통화 녹취 STT → 자동 기록 (FR-E7) | VoIP/CTI 연동 필요(전화는 시스템 밖) + 녹취 고지·동의 정책 선행 필요 | 기록 구조화 파이프라인이 입력 소스 불문(수기 메모 ↔ STT 전사)이라 뒷단 무변경으로 확장 가능. 전사 요약은 실시간 불필요 → Batch 처리 대상 |
| 화상/전화(VoIP) 연결 | 상담 자체는 기존 전화로 수행됨. 과제의 문제는 "상담"이 아니라 "운영" | 예약에 연락처 스냅샷 보관 |
| 예약 변경(FR-C10) | 취소 후 재예약으로 대체 가능, 우선순위 낮음 | 상태 기계에 RESCHEDULED 전이 여지 |
| 가족 동의 절차(FR-A4) | 법무 정책 의존 | Subject 테이블에 동의 관련 컬럼 확장 여지 |

## 3.3 LLM 기능을 MVP에 포함한 근거

단순 편의 기능이 아니라 **P6(기록 비표준)의 채택률 문제**를 푸는 수단이다. 구조화 입력 폼을 강제하면 상담사 부담이 늘어 기록 품질이 떨어지거나 형식적으로 작성된다. 자유 메모(기존 습관 유지) → LLM 구조화 → 상담사 확인·수정의 흐름은 부담을 늘리지 않으면서 데이터 표준화를 달성한다.

두 기능은 처리 방식 요구가 달라, 서로 다른 아키텍처 패턴을 의도적으로 대비시켰다:

- **기록 구조화**: 상담사가 화면에서 대기 → **동기 호출 + structured output**(스키마 강제)으로 수 초 내 응답
- **사전 브리핑**: 예약~상담 사이에 수 시간~수 일의 여유 → **비동기 배치 처리**로 비용 최소화. 실패 시에도 상담은 정상 진행(참고 자료일 뿐)이므로 핵심 플로우와 격리

## 3.4 MVP에서 검증하려는 가설

1. QR 진입 + 가용 시간 시스템화로 예약에 운영자 개입이 0이 된다 (P1, P4)
2. 상태 기계 + 자동 리마인더로 노쇼가 줄고, 최초로 노쇼율이 **측정**된다 (P5)
3. LLM 보조 구조화 기록으로 전환율·관심 제품 데이터가 **자동으로 쌓인다** (P6~P9)
